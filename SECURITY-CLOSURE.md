# Security closure — 2026-10-26

## Applied database change

`drizzle/migrations/0024_close_legacy_order_inserts_public_product_projection.sql`

- Revoked direct INSERT from PUBLIC, anon and authenticated on orders, order_items and order_sellers.
- Removed `Users create own orders` and `Users insert order items for own orders` policies. No INSERT policy existed on order_sellers.
- Kept existing SELECT policies and permissions unchanged.
- create_order_secure remains executable by authenticated and service_role, not anon/PUBLIC.
- public_products is an explicit security-invoker, security-barrier catalog view. It filters approved, unsold products and excludes reserved_by, rejection_reason and stock_alert.
- Direct products reads use column-level SELECT grants, excluding those three private fields for both anon and authenticated. Direct wildcard reads therefore fail instead of exposing the fields.
- get_my_product_reservations returns only product_id and reserved_by_me for the signed-in caller; no reservation owner UUID.
- get_managed_products returns full rows only for admin, seller owner, or active collaborators with products.view, optionally scoped to a store.

## Application changes

Storefront product reads migrated in index, explorar, produtos, categorias, loja.$id, produto.$id, favoritos, perfil.favoritos, sitemap and CartContext. Product detail uses the private boolean ownership RPC. Admin, seller and collaborator product lists use get_managed_products. Design and visible copy were not changed. Architecture rules were recorded in AGENTS.md. Types regenerated by the migration tool.

## Checks passed

- `bun test tests/security-boundaries.test.ts`: 12 passed, 33 assertions.
- Real anonymous requests: public_products returns 200 without private fields; reserved_by and wildcard products queries rejected (401 for anonymous, 403 for signed-in reserved_by).
- Real authenticated direct INSERT requests to all three order tables rejected with 403 / 42501.
- Authenticated create_order_secure reaches server validation: invalid nonexistent product rejected with `Produto não encontrado`, rather than an EXECUTE permission error.
- Anonymous browser: home, explorar (50 visible products), categorias, produtos and product detail render. Anonymous favoritos retains its existing login redirect.
- Authenticated browser: explorar, favoritos, perfil/favoritos, admin products (214 rows), carrinho and checkout render. An actual available product was added to the cart; checkout displayed its contact form and summary. Temporary cart entry and reservation were removed.
- Admin full product records remain available through the protected RPC.
- Preview build reports build OK; browser pageerror collection empty.

## Not verified / limitations

- A complete successful order creation and UI read-back was NOT performed. The read-only sandbox SQL identity cannot SET ROLE authenticated or execute create_order_secure; creating an actual production order could notify the real seller. No fake orders or users were created. Full order submission remains an explicit test gap, not a passed test.
- Seller/collaborator browser sessions were not impersonated. Server-side access predicates and grants were inspected; admin was tested with the requesting account.
- New frontend queries are in the preview, not automatically published. The database restrictions are already active on the shared backend; publish the frontend changes promptly because the previously published product detail still requests all products columns.
- Existing unrelated city/signup tasks in roadmap.md are outside this security request and remain untouched.
